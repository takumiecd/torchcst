# RTX 4090での有理式半径LinearのボトルネックとAtom順序

[English](rational-q-atom-order-4090-20261120.md) | **日本語**

[中間結果を保存する直接Plan](rational-q-saved-response-4090-20261120.ja.md)を
プロファイルした。RTX 4090（SM89）、PyTorch 2.9.1+cu128、eager IEEE FP32。
正方形のM8 cell mass、`rational_radius`、単位間隔の周期グリッドを使い、
特記がない場合は入力128行。

## 時間の内訳

幅16384・524,288 Atom。[幅比較](rational-q-crossover-4090-20261120.ja.md)と同じく
幅4096で学習したQueryのAtom分布を広いグリッドに展開した。
表はforwardとbackwardを別々にトレースしたCUDAカーネルの時間で、3測定の平均。
計測器なしの合計は129.75 ms。フーリエ重み展開は合計78.11 msで、
forwardが48.14 ms、backwardが29.97 msだった。

| 処理 | Forward (ms) | Backward (ms) |
| --- | ---: | ---: |
| Atomごとの応答 | 24.66 | 24.36 |
| Atom勾配 | — | 38.86 |
| 広いタイルの係数集約 | 16.75 | 18.19 |
| 出力先のサイトで係数を評価 | 2.29 | 2.34 |
| 入力側のフーリエ集計 | 0.46 | 0.47 |

幅16384で入力を32・64・128・256行にしたときのforward＋backwardは
31.08・64.61・129.75・257.53 ms。幅8192・128行では、Atom数を
131,072から262,144に増やすと23.97から53.61 msになった。

幅16384の実測用データで物理半径の中央値は95.63サイト、レベル9は32.8%。
x・dY・振幅・中心を固定し、半径の学習値を一律0、0.5、1にしたときの合計は
63.93、129.40、69.69 msだった。一律0.5では応答の合計が58.51 ms。
一律1では全半径が512になり、応答の合計は3.29 ms、広いタイルの集約は
59.03 msだった。これらの対照では半径と区分の分布が同時に変わる。

Atom勾配はCUDAの1レーンが1 Atomを担当して入力行を順次処理し、
入出力の応答とフーリエ集計を読む。応答カーネルは1レーンが1 Atomと8入力行を
担当する。元のAtom順では隣り合うレーンが異なる半径の分岐に入り、離れたタイルを
参照することがある。同じ区分内のAtomを並べ替えると、Atomの値を保ったまま
この条件を変えられる。今回測定したのはカーネル時間で、キャッシュ・分岐・DRAMの
ハードウェアカウンタは取得できなかった。読み出しの局所性はコードと順序だけを
変えた対照実験からの推定。

コンパイル時の報告では物理Atom勾配カーネルは127レジスタ、スタック1,128バイトで
レジスタのスピルも報告されなかった。行ごとの重み付き和を先に取る候補は、
FP64のプロフィール係数生成を維持して101レジスタ、スピル0だった。同条件の
Atom勾配カーネルは38.90 msから40.00 ms、optimizer込みの1更新は
134.17 msから134.60 msだった。候補と証拠は別の研究ブランチに保存した。

## Atom順序だけを変えた実験

同じAtomと同じCUDAバイナリを使用。事前に並べ替えてから計測した。
勾配を元の順に戻し、出力と一階勾配の差が0であることを確認した。

| Atomの順序 | Forward＋backward (ms) |
| --- | ---: |
| 元の順序 | 131.84 |
| 半径区分 | 77.02 |
| 半径区分、入力タイル | 42.11 |
| 半径区分、出力タイル | 41.54 |
| 半径区分、入力タイル、出力タイル | 30.80 |

入力タイルを優先した最後の条件では、forwardの応答は24.26から1.32 ms、
backwardの応答とAtom勾配はそれぞれ9.66、9.33 msだった。
実験コミット `5dd4c263` に4096→1024のFFN downでの両タイルの並べ替えがある。
従来の正方形Planにも集約用のソート済みインデックスがあり、応答・Atom勾配は
元の物理Atom配列順を使っていた。

## CSTLinearで呼び出しごとに並べ替える

研究Plan `cuda_rational_radius_wide_ordered` は現在の半径と中心から毎回キーを
作り、物理Atomを並べ替えてからCUDAカーネルを呼ぶ。勾配はautogradで
元のParameter行に対応づける。3経路とも同じCUDAバイナリを使用した。
各経路を別プロセスで起動し、順序を反転した2測定の中央値を平均した。
各プロセスで8回のウォームアップ後に24回を計測した。並べ替え版はキー生成、
ソート、Atomのコピー、勾配の復元を含む。ピークはforward＋backward中の
PyTorchの割当量。

| 幅 / Atom数 | 保存版のF+B (ms) | 並べ替え版のForward (ms) | 並べ替え版のBackward (ms) | 並べ替え版のF+B (ms) | フーリエ重み展開のF+B (ms) | ピーク 保存 / 並べ替え / 展開 (MiB) |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 4096 / 32N | 21.91 | 3.21 | 5.92 | 9.15 | 6.23 | 234.74 / 235.74 / 588.11 |
| 8192 / 16N | 24.33 | 3.08 | 6.89 | 9.98 | 20.12 | 314.99 / 315.99 / 2211.76 |
| 8192 / 32N | 53.44 | 4.52 | 11.48 | 15.99 | 21.02 | 470.49 / 472.49 / 2238.96 |
| 16384 / 32N | 130.62 | 7.57 | 23.64 | 31.23 | 78.01 | 938.99 / 942.99 / 8757.88 |

幅16384のoptimizer込みの更新時間は、保存・並べ替え・展開の順に
134.25、32.92、78.49 ms。ピーク割当は962.97、966.99、8773.88 MiB。
全4条件で並べ替えと保存の出力・一階勾配の全テンソルがバイト単位で一致した。
CUDAの対象テストは14件通過、CPU全体は2,206件通過、2,585件スキップ。

[7層の容量試験](rational-q-saved-response-4090-20261120.ja.md)で並べ替え版は
3更新を完了し、保存版と各点の損失が一致した。2〜3更新目の平均は0.219秒、
ピークは4.06 GiB。前回の保存版は0.915秒と4.03 GiBで、素のDenseは
初回のoptimizer更新でOOMだった。合成データによるeager FP32の容量試験。
