# Explicit M8 c16 FFN cohort

English (canonical) | [日本語](m8-ffn-c16-20261110.ja.md)

Prepared for the owner-requested Atom-capacity comparison. The new private
`lm_c16` physical/envelope Algorithms admit only512↔2048,16384 atoms, M8,
base1/merge2, origin0/spacing1, FP32 and1..256 eager rows. The envelope adapter
retains radius[.5,50], amplitude≤32 and the complete radius VJP. Both old c8
Algorithms still reject16384 atoms; public/default registration is unchanged.

All CUDA arithmetic, physical LM execution, coordinate decoding, initialization
and optimizer implementations are reused unchanged. Only a new metadata/adaptor
module is added under runtime; benchmark-local registration names the new Plans.
This does not make a new fixture certified for the central submission pipeline.
No new kernel, profile, LR, epsilon, radius schedule or Graph support is introduced.

Before learning, require metadata/roundtrip/rejection checks, existing native
regressions and A16384 retained/multiple-forward checks at rows1/7/128/256 in
both directions. The task consumer must compare full-A Y,dX and each raw field
with CPU FP64 factors at initial/final state: maxabs≤3e-4 AND relativeL2≤1e-4
per tensor/field. Retain older component-criterion violations; do not relax this
predeclared rule. Require exact checkpoint/observer next-update equality and
finite FP32 moments/clocks. GPU validation and task results are pending here.

The research consumer freezes the source and data, retains old c8/Dense/DST
controls with verified manifests, and records that separate-job timing is only
exploratory. The task is an all-eight-FFN capacity intervention, not a universal
Atom lower-bound study or public default adoption.
