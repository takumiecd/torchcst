# RTX 4090での広幅rational-radius LinearのAtom勾配のタイル順最適化

[English](rational-q-axis-gradient-4090-20261120.md) | **日本語**

[従来のPlan](rational-q-reverse-order-4090-20261120.ja.md)では、Atom勾配の
入力側と出力側をどちらも入力タイル順で計算する。明示的な研究用Plan
`cuda_rational_radius_wide_axis_gradient` は、保存済みの出力タイル順で
出力側の微分を計算し、入力タイル順で入力側の微分と振幅勾配を計算する。
最初のカーネルはAtomごとに出力側の2つのスカラーを入力順の位置に書き戻す。
2つ目のカーネルは半径の項を足し、勾配を確定する。どちらも既存のFP64の
プロファイル係数計算とFP32の信号微分を使う。

## 計測時間とメモリ

RTX 4090（SM89）、PyTorch 2.9.1+cu128、CUDA Toolkit 12.6、eagerのIEEE FP32、
M8 cell mass、128行、幅Nにつき32N Atom。両版で同じネイティブバイナリとAtomを使い、
幅4096の保存済みQuery Atom分布をより広い条件に複製した。各版を独立した
2プロセスで、実行順を入れ替えて計測した。各プロセスで8回ウォームアップし、
24回計測した中央値を平均した。更新にはCSTAdamWを含む。メモリ欄は
2回の完全ステップ計測で最も高かったピークで、両版で値が一致した。

| 幅 | Backward、従来 → 分割 (ms) | F+B、従来 → 分割 (ms) | 更新、従来 → 分割 (ms) | ピーク割当 / 予約 (MiB) |
| --- | ---: | ---: | ---: | ---: |
| 4096 | 4.59 → 3.79 | 7.89 → 7.09 | 7.70 → 6.78 | 242.74 / 272 |
| 8192 | 8.27 → 6.18 | 12.88 → 10.97 | 12.89 → 10.45 | 486.49 / 506 |
| 16384 | 15.72 → 10.51 | 23.25 → 18.06 | 24.15 → 18.33 | 970.97 / 1252 |

幅16384で別に4回プロファイルしたところ、従来のAtom勾配カーネルは9.21 ms、
分割した2つのカーネルは合計4.09 msだった。分割用の一時バッファはこの幅で
4 MiBあり、割当時点の使用量は従来のステップピーク内に収まった。
2カーネルは新しいbackward時間の約39%を占める。

既存の幅16384・7層の容量検証では両版とも3更新を完了し、各更新の損失が一致した。
更新2–3の平均時間は165.43 → 128.35 ms。ピーク割当は両版4183.00 MiB、
ピーク予約は4364 MiBだった。この容量検証では合成データを用いた。

## 正しさと適用範囲

計測した3幅すべてで、出力、入力勾配、両中心の勾配はビット単位で一致した。
幅をまたいだ相対L2差の最大は振幅が `5.33e-8`、半径の座標が `2.75e-7` だった。
分割で半径の寄与を加算する順序が変わる。独立したFP64参照との全一次勾配の照合を含む
幅広CUDAテストは11件成功した。CPUテストは2,206件成功、2,585件スキップ。
このPlanはeager用として研究カタログに登録した。

## 再現手順

計測したソースは `f55fc76d707cafe85c7c5a6f2e4eba7e363d3814`。
`output/rational-q-axis-atom-grad-20261120-01` にソースアーカイブ、ビルドと計測ログ、
`verified/summary.json` を保存した。GPUホスト上の実験ディレクトリで
`bash build-axis.sh` を実行すると拡張のビルドとCUDA参照テストを行う。
成功した計測ではテスト後のバイナリを固定し、`bash run-replay.sh` で
両版の再現計測・プロファイル・7層の容量検証を実行した。
ビルドとテストのPIDは73181、計測のPIDは75172。最初の2試行では既存のNinjaと
NVIDIAヘッダーを探索パスに加える必要があった。最初の計測はpytestがJITバイナリを
再ビルドしたためハッシュ照合で停止し、テスト後のバイナリを固定して両版を計測した。
