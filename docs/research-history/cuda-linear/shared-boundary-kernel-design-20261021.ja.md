# 切替sigmaで形を一致させるkernel設計

2026-10-21。ユーザーの要請は、Fourier係数の後付け補正や混合で整合させるのではなく、
切替sigmaで両側の形が一致することを出発点として数式を組むこと。
旧CPU v1/v2の候補は採用しない。GPU最適化の再開ではない。

## 先に固定する条件

r=x-mu、支持は[-L,L]、外側0、基本周期2L。
あるLのまま局所評価から共有評価へ切り替えるsigmaをsigma*とする。
raw profileの一致条件は区間全体で

\[
q_N(r,\sigma_*)=q_F(r,\sigma_*),\qquad
\partial_\sigma q_N(r,\sigma_*)=\partial_\sigma q_F(r,\sigma_*).
\]

空間微分も一致し、同じsampled L2と全積floorを使う。
端の値だけをそろえることは、山全体の一致とは異なる。

距離rの有限次数多項式と有限Fourier級数は、非定数関数として開区間で厳密一致できない。
両者はその区間の内部で解析的であり、一致すれば解析接続によって同じ関数になるが、
周期的な多項式は定数に限られる。区分多項式でも非空の多項式pieceで同じ問題が起きる。
従って、純粋な距離多項式という条件を維持するなら近似誤差が残る。
厳密一致を約束した上で両係数を最適化する、という方針にはしない。

## 共通の関数を異なる式で評価する候補（未採用）

\[
z(r,L)=\frac{1+\cos(\pi r/L)}2,\qquad
q(r;\sigma,L)=z^2\sum_{j=0}^{M-2}a_j(\sigma/L)z^j\quad (|r|\le L).
\]

a_j>=0、sum a_j=1なら非負・中心peak1。端ではzが2次で消えるため、qはC3で外側0へ接続する。
これはrの純粋な多項式ではなく、cosine座標zの多項式である。
小sigmaの直接評価にもcos1回とHorner積和が必要。この費用をゼロとは扱わない。

整数n>=0について厳密な恒等式

\[
z^n=\sum_{k=-n}^{n}\frac{\binom{2n}{n+k}}{4^n}\,e^{ik\pi r/L}
\]

がある。従って同じqの共有評価用Fourier係数は

\[
c_k(\sigma/L)=\sum_{j=0}^{M-2}a_j(\sigma/L)
  \frac{\binom{2j+4}{j+2+k}}{4^{j+2}},\qquad |k|\le M,
\]

範囲外のbinomialは0とする。係数のフィット・支持端補正・native/Fourier混合は不要。
両者は同じ関数なので、あるLを保った評価方式の切替では全sigmaで値と微分が一致する。
L2も同じqのFourier係数とgeometry momentで計算でき、方式切替のための交差項は生じない。

係数a_jから実際の幅を決める設計は別途必要。sigmaという名前を付けただけで、
任意のsigmaを標準偏差として実現できるとは主張しない。
LからL/2へkernel定義を変える接続も、この恒等式だけでは解決しない。

後続の[幅校正・dyadic接続のCPU検討](scale-matched-cosine-cpu-20261021.ja.md)で、
この非負係数候補の幅範囲はM4/8とも1octave未満と確認した。
同ノートの2piece緩和候補は別の関数族であり、本候補が完成したと解釈しない。

## 恒等式の数値例だけを確認

例 `q=(1-t)z²+t z^M`、M4/8、20状態ずつ。
t=.5-.25*tanh(log(sigma/sigma*))は検査用の滑らかな係数であり、物理幅への校正ではない。
中心0/.037/.49/1、sigma .1/.99/1/1.01/10、L=1で直接式と級数を比較した。
原本はignored `output/shared-boundary-identity-20261021/results.json`。

| 最大絶対誤差 | M4 | M8 |
| --- | ---: | ---: |
| 値 | 4.45e-16 | 5.56e-16 |
| 中心微分 | 1.34e-15 | 2.67e-15 |
| 係数を通じたsigma微分 | 6.25e-17 | 1.32e-16 |

これは恒等式の確認だけ。sigmaの物理幅、sigma_min=.1、dyadic L接続、M4/8の形状範囲、
正規化込みの速度・容量・GPU精度は未検証。新しいKernelSpec/公開dispatcherには登録していない。
