# M8 c16 FFNの明示的な実行条件

[English](m8-ffn-c16-20261110.md) | 日本語

ユーザーが依頼したAtom数比較の準備。新しいprivateな`lm_c16`のphysical/envelope Algorithmは、
512↔2048・16384 Atom・M8・base1/merge2・origin0/spacing1・FP32・1..256行のeagerに限定する。
envelopeは半径[.5,50]・振幅≤32と半径の完全なVJPを保つ。
元のc8 Algorithmは16384 Atomを引き続き拒否し、公開の既定登録は変更しない。

CUDAの計算、physical LM実行、座標decode、初期化、optimizerは全て既存のまま再利用する。
runtimeにはmetadata/adapterの新moduleだけを追加し、benchmark内Registryに明示的なPlanを登録する。
中央の結果投稿pipelineで新fixtureが認定されたという意味ではない。
新kernel/profile/LR/epsilon/半径schedule/Graph対応は追加しない。

学習前にmetadata・roundtrip・拒否条件、既存native回帰、A16384で両方向・1/7/128/256行の
retained/multiple-forwardを確認する。consumerは初期/終端の全Aについて、Y/dX/raw各fieldを
CPU FP64 factorと比較し、それぞれmaxabs≤3e-4かつrelativeL2≤1e-4を要求する。
旧component基準への違反数も保持し、事前基準は緩和しない。
保存とobserver後の次更新完全一致、有限FP32 momentと時計も必須。ここではGPU/タスク結果は未確認。

研究consumerはsource/dataを固定し、manifest検証済みの既存c8/Dense/DSTを対照に使う。
別jobの速度比較は探索的と記す。全8FFNのAtom容量介入であり、普遍的Atom下限探索や既定採用ではない。

最初のGPU実行はC++のpacked_check_scopeが8192限定のため8テストで拒否され、学習前に停止した。
88件は合格。失敗compact f99dd0bf295ee5533003b351d88add72f244ba984dbe62718d47a9a5396a1bfdを保全・検証済み。
修正は専用RADIUS_LM_C16ビルドでC16だけを許可し、通常ビルドのガードを維持する。
既存packed.executeにextension取得hookを追加し、c16だけ別binaryを選ぶ。
packed_rows.cuhではこの条件付きhost guardだけを変更し、数値kernelは変更しない。
通常CPP入口がA16384を、新binaryがA8192を拒否するGPUテストも追加した。関連GPU検証は98件となる。
修正後のCPUは2260合格・2664 skip。GPU再検証は別source/別jobで行い、失敗sourceは変更しない。
