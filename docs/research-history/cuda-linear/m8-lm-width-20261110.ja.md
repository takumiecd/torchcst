# c64固定M8 LM幅の専用受付

[English (canonical)](m8-lm-width-20261110.md) | 日本語

次のタスク実験ではTinyStoriesの4ブロックFFNで幅512/1024/2048、expansion4、
8写像すべてを置換し、各写像A=64 sqrt(d_in d_out)=128*widthとする。
`lm_width.py`に物理/envelopeの専用Algorithmと`RADIUS_LM_WIDTH`専用buildを加える。
上記6組のshape/count、FP32 rows1..256、M8/base1/merge2/spacing1/origin0、
radius[.5,50]、振幅上限32だけを許可する。変更はhostのshape受付のみで、
数値bodyとordinary/c16/budget buildの受付は不変。benchmark内Registryだけに登録し、
公開defaultには採用しない。

metadata/plan往復は6組と2座標宣言を検査する。学習前に実CUDAでretain、複数forward、
非連続入力、独立task oracleを確認する。ローカルのGPU skipをpassと数えない。
全Aの独立FP64 Y/dX/4 rawフィールドで各maxabs<=3e-4かつrelativeL2<=1e-4を固定する。
optimizer/observer round-trip、checkpoint・復元validationはcst-research側の幅実験で
確認する。Dense/CST/Dense-mask DSTをA=mask1の数で比較し、LR全候補を残して、
短期・長期のデータとschedule horizonを揃える。この文書は受付設計の記録であり、
性能・精度は実実行前の未確認状態である。

未mergeのM8 budget workを土台とし、祖先には中止済みM16 stackも残る。
統合前にM8変更を抽出すること。M16 PR closeはそれらのmerge許可ではない。
main merge、source/証拠削除、公開採用、収束・スケーリングの主張は行わない。
