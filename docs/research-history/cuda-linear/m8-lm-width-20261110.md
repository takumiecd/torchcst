# Private fixed-c64 M8 LM width admission

English (canonical) | [日本語](m8-lm-width-20261110.ja.md)

The next task study uses four-block TinyStories FFNs at width512/1024/2048,
expansion4, all eight maps replaced, A=64 sqrt(d_in d_out)=128*width per map.
`lm_width.py` adds an isolated physical/envelope Algorithm pair and a dedicated
`RADIUS_LM_WIDTH` extension build. Only the six shape/count pairs, FP32 rows1..256,
M8/base1/merge2/spacing1/origin0, radius[.5,50], amplitude cap32 are admitted.
Only host shape admission changes; numerical bodies and ordinary/c16/budget
build admission remain unchanged. Registry is benchmark-local, not public default.

Metadata/round-trip tests cover all six pairs and both coordinate declarations;
actual CUDA retained/multiple-forward/noncontiguous tests and independent task
oracles are required before learning. Do not count local GPU skips as passes.
Task qualification uses full-A independent FP64 Y/dX and all four raw fields,
maxabs<=3e-4 and relativeL2<=1e-4 per field. Optimizer/observer round-trip and
checkpoint/reloaded-validation checks are in cst-research's width study.
Compare Dense, CST and dense-mask DST with A=mask-one count, retaining all LR
candidates and matched short/long data and schedule horizons. This file records
admission design only; performance and quality are pending actual execution.

This branch builds on unmerged M8 budget work and still contains the abandoned
M16 stack in its ancestry. Before any integration, extract the M8 changes from
that stack; closing the M16 PRs did not authorize their merge. No main merge,
source/evidence deletion, public adoption or convergence/scaling claim.
