# RTX 4090での有理式半径フーリエLinear

[English](rational-wide-fourier-4090-20261120.md) | **日本語**

二つの明示的な有理式半径Planを `CSTLinear(x)` から実行した。
展開Planはフーリエ係数から一時的な重みを作って行列積を使う。
直接Planは階層化した射影と物理半径の逆伝播を実行する。
両方とも学習可能な `[振幅, q, 出力中心, 入力中心]` を同じ式で変換した。
RTX 4090、Torch 2.9.1+cu128、FP32、TF32無効、eagerで計測した。

各幅・Atom数で、TinyStoriesのシード17・4,882更新のチェックポイントから
最初のQuery射影を復元した。初期Atom、シードで生成した入力とMSEの目標値、
eagerのCSTAdamW設定（学習率0.003、betas 0.9/0.95、weight decay 0）を揃えた。
射影一層の学習ステップ全体を、逆伝播とoptimizerまで測った。
順序を反転した2回の計測を行い、それぞれ8更新のウォームアップ後に24更新を計測した。
時間はGPU同期を含む中央値の2回平均、割り当て・予約メモリはそれぞれ2回中の最大値。
表の各組は **展開 / 直接** の順。

4096幅では、計測した4条件すべてで直接Planの割り当てピークが低かった。
2048幅では、128行で直接Planのピークが低く、256行で逆転した。
更新時間は8条件すべてで展開Planの方が短かった。

保存済みAtom全体を使って、出力、入力勾配、各Atom項目の勾配を照合し、
相対L2差の最大は3.70e-6だった。別のGPUテストでは、各幅とAtom数で両Planを
CPUのFP64フーリエ参照と比較した。全サイトを対象とし、両端値を含むqの範囲を
128個の有効Atomで検証した。計測はeagerの半径変換と一階微分を使った。

既存runnerでは、保存済みAtomの代わりに初期化したAtomでも同じPlanを実行できる。

```bash
python -m benchmarks.cuda.linear.run \
  --plans benchmarks/cuda/linear/plans-rational-wide.json \
  --case benchmarks/cuda/linear/cases/rational-wide-4096-r128-c32.json \
  --output output/rational-wide-4096-initial.json
```
