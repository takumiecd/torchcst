# 小ブロックの直接計算で入力を再利用する（A100）

2026-09-26。[小ブロック比較](block-strip-study.ja.md)に続く実験。

続報: [複数出力特徴で入力を共有する直接計算](block-output-sharing.ja.md)。
CST tileを64×64に固定し、同じatom表・同じchart・同じ入力で旧直接版と比較する。
各ケース内の全経路は同じWを表し、前回のようにtile shape間で幾何を変える比較ではない。

## 結論

同じ64×64 CST配置を保ったまま、入力・座標の再利用と実行分割を変更して直接版を改善した。
4096²/M128の確認測定は47.102→14.842ms（3.17倍）、4096²/M512は192.194→56.879ms（3.38倍）、
8192²/M128は119.988→46.643ms（2.57倍）。全Wを展開せず、追加割当は旧直接版と同じ。

8192²では同じ配置の融合版55.253msより直接版が速い。一方、dense 6.406msに対しては約7.28倍の時間。
4096²でもdenseとの差は約10.6〜10.9倍残る。現時点でdenseに並ぶ速度には達していない。
BM16/64/128の中では低atom密度の3条件でBM64が最速だったため、次の直接版の比較基準にする。

## 変更

`BlockStripLinear(...)(x, backend="triton_reuse", batch_tile=...)`を実験用に追加。
GPU forwardのみ。公開CSTLinear APIは変更していない。

1. 列断片を先に読み、入力をレジスタに保持して候補atom間で再利用する。
2. 円方向のsite座標をatomループの外で計算する。
3. 実行上の列幅BKを64に合わせる。旧版はCST tile幅64に対してBK128を使っていた。
4. 入力行方向BMを16・64・128で比較し、一度計算したatom寄与を多くの入力行に共有する。

BMとBKはCUDA実行上の分割であり、CSTのtile shapeや学習対象の幾何を変更しない。
重みタイル・全W・出力の部分和バッファをグローバルメモリに作らず、出力の書き手も一つのまま。
全Wを保持するdenseは比較用で、CSTカーネルはそのWを読まない。

旧版とreuse版の比較には入力再利用・列幅の変更・分岐の削減が含まれる。
単独のcache効果を測った実験ではない。reuse版同士のBM比較は同じアルゴリズムで行う。
BM増加によるレジスタ使用量はcompiler resource情報で確認する。

## 条件

- A100 80GB PCIe、MIG 3g.40gb、42 SM。Torch2.6.0+cu126、Triton3.2.0。
- FP32、TF32無効、Strip + Torus / raw Triweight、seed21。
- 4096²/M128/8192 atoms、4096²/M512/8192 atoms、8192²/M128/16384 atoms、
  4096²/M128/131072 atoms（32 atoms/tile）。各ケースのCST tileは64×64。
- 所属判定・I/B分類・sort・pack込みCUDA Graph時間。3ラウンド、rep20ms、中央値。
- 通常Python実行の壁時計時間は含めない。denseのW生成は計測外。
- 初期配置のみ。境界をまたぐ移動は数値テストで確認するが、性能表はIのみの条件。
- ハードウェアのcache hit率や実HBM転送量は測っていない。CUPTIはカーネル時間の所在を示す。

## レジスタと計算時間の所在

4096²/M128のcompiler resource。全て4 warps/block。

| BM | registers/thread | spills | shared bytes |
| --- | ---: | ---: | ---: |
| 16 | 56 | 0 | 64 |
| 64 | 113 | 0 | 256 |
| 128 | 203 | 0 | 512 |

BM128は一度の寄与評価をより多くの入力行に使うが、レジスタ保持量も増える。
今回の低atom密度3ケースではBM64より遅かった。単にBMを増やす方法では頭打ちになる。
131,072 atomsではBM128が少し速いため、すべての密度でBM64が最適とは言わない。

CUPTIのカーネル時間（初回の時間測定後、3ステップ平均）。注釈範囲は集計から除外。

| --- | ---: | ---: | ---: |
| old_bm16 | 47.167 | 46.635 | 98.87% |
| reuse_bm64 | 14.876 | 14.344 | 96.42% |
| reuse_bm128 | 16.980 | 16.449 | 96.87% |

## 次の基準

低atom密度では`triton_reuse`のBM64を直接版の基準にする（同backendの既定値）。
旧`triton_direct`は比較用として保持する。8192²では直接版が同じ64×64の融合版より速くなったが、
denseにはまだ約7倍の差がある。全W展開なしのまま、次は複数出力行での入力共有と
warp内の仕事分担を検討する。GPU backwardや公開backendへの統合は別の段階。
